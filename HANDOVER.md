# Korda Syntax — разбор передачи проекта

Проверено 08.09.2026 по архиву syntax-main.zip. Это исходники корпоративной AI-системы для компании Корда, а не подтверждённый полный комплект действующей инфраструктуры. README не содержит инструкции развёртывания. Номер пакета 0.0.0 не позволяет установить релиз. Истории Git в архиве нет.

## Что запущено

- Локальный просмотр: http://127.0.0.1:3000, логин `demo`, пароль `demo`.
- Сервер слушает только 127.0.0.1. В интерфейсе показана жёлтая отметка локального режима.
- Это настоящий интерфейс проекта с отдельным добавленным локальным хранилищем, не подключённый к прежней базе.
- Тестовые данные сохраняются в `.local/preview-data.json`. ИИ, тендерный поиск, облачные файлы и прочие внешние API возвращают явное сообщение о недоступности.
- Это режим просмотра, не полная эмуляция всех операций и не production-сервер.
- Перезапуск: двойной щелчок по `START-LOCAL.cmd`. Закрытие окна сервера / Ctrl+C останавливает его. Если порт занят текущим экземпляром, второй запуск не нужен.
- После изменений интерфейса: `npm run build:local`, затем `npm run start:local`. На этом компьютере npm доступен через `node E:/syntax/.tools/package/bin/npm-cli.js`.

Обычный backend также был отдельно запущен на порту 3001 и после проверки остановлен: `/health` вернул 200, попытка входа — 500 `Database Connection Failed`, потому что отсутствует `FIREBASE_SERVICE_ACCOUNT`. Это подтверждённый блокер работы оригинальной авторизации.

## Оплата

В проверенных исходниках и зависимостях не найдено интеграции приёма платежей: нет оформления платежа, webhook подтверждения оплаты или биллинга подписок. Упоминания финансов относятся в том числе к CRM, сметам и аналитике. Наличие платёжной системы в иной версии проекта неизвестно.

Если нужна оплата клиентами за площадку, это отдельная разработка: надо определить провайдера, получателя платежей, товары/тарифы, разовые платежи или подписки, валюту, тестовые ключи, параметры webhook и правила выдачи/прекращения доступа. Точные реквизиты и требования зависят от выбранного провайдера. Оплата API Google/Checko/Контур отдельно от оплаты вашими клиентами.

## Найденные проблемы перед боевым запуском

1. `api/db.js` выполняет list/get/set/delete и другие действия без полноценной проверки серверной сессии и ролей. Переданные клиентом идентификаторы не заменяют проверку токена.
2. Там же пароли сравниваются напрямую с полем документа; bootstrap позволяет создать/обновить администратора с фиксированным паролем. Нужна переработка авторизации, серверная проверка прав и ограничение/удаление bootstrap.
3. Обработчики ИИ и ряда вспомогательных API также требуют контроля доступа, лимитов и защиты от несанкционированных расходов.
4. RAG и Windows-агент используют фиксированные секреты/значения по умолчанию. Заменить, вынести в конфигурацию и проверить историю их использования.
5. `dotenv.config()` вызывается в теле `server.js` после статических импортов, но часть модулей читает env на верхнем уровне. Для реального запуска ниже предложен `node --env-file=.env server.js`; обычный `npm start` требует исправить порядок загрузки env.
6. В нескольких RAG-обработчиках `initFirebase()` вызван без await; возможна гонка инициализации.
7. `node-cron` комментирует расписание как UTC, но не задаёт timezone. В текущем часовом поясе расписание может отличаться от ожидаемого.
8. `npm run dev` запускает только Vite на 3000; прокси к Express не настроен. Для полного реального локального запуска требуется production-сборка + Express либо отдельные порты с Vite proxy.
9. В архиве есть диагностические/миграционные скрипты, которые обращаются к старому домену и меняют данные. Они не запускались. Windows EXE также не запускался.

Это первичный разбор запуска, не полный аудит безопасности.

## Проверки

- Установлены 660 пакетов по package-lock через `npm ci --ignore-scripts --no-audit --no-fund`.
- `npm run build:local` — успешно.
- `npm run build` — успешно.
- `tsc --noEmit` — успешно.
- Vite предупреждает о крупном основном JS-бандле и смешанных статических/динамических импортах; сборку это не блокирует.
- В браузере проверены вход, главный экран, тендеры, конвейер, создание диалога и наличие диалога после перезагрузки.
- Оригинальный Express стартует, но вход не работает без базы; он остановлен после диагностики.
- Полноценные облачные сценарии, биллинг, CRM и доступность моделей не проверены без доступов.

После получения доступов и исправления блокеров: скопировать `.env.example` в `.env`, заполнить, восстановить данные, выполнить `npm run build`, затем `node --env-file=.env server.js`. Демонстрационный аккаунт относится только к `local-server.js` и в настоящей базе не создавался.
